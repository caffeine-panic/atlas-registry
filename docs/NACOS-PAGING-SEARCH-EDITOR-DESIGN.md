# Nacos 分页、标识搜索与配置编辑器优化方案

- 状态：已实现并完成本地自动门禁与 Nacos 2.x / 3.x 真实服务复验
- 范围：Nacos 配置列表与标识搜索；三种协议共用的资源详情编辑器
- 相关决策：[ADR-0002](./ADR-0002-CODEMIRROR-EDITOR.md)、[ADR-0003](./ADR-0003-NACOS-BOUNDED-IDENTIFIER-SEARCH.md)
- 领域语言：[CONTEXT.md](../CONTEXT.md)

## 实现验证

2026-08-28 已通过 `format:check`、ESLint、36 项前端行为测试、TypeScript/Vite 构建、rustfmt、Clippy `-D warnings` 与完整 Rust 测试。另使用仓库兼容脚本在 loopback 临时容器中完成以下真实服务契约复验：

- Nacos 2.5.2，v2 API：通过。
- Nacos 3.2.3，v3 API：通过。

## 背景

当前 Nacos 配置列表在服务端按页读取，但中栏只以“加载更多”追加结果；“筛选当前已加载资源”只过滤前端已有行，因此无法命中尚未加载的后续页。界面同时存在本地筛选与远端搜索，虽然远端搜索已使用 Nacos 的模糊查询能力，但两个入口的作用范围容易混淆。

资源正文目前使用原生 `textarea`，即使 Nacos 返回 JSON、YAML 等 `contentType`，也只显示类型标签而没有语法高亮或显式校验。

## 目标

1. Nacos 配置列表使用明确的页式导航，每次只展示当前页。
2. Nacos 模糊搜索覆盖当前 namespace 的全部配置，并同时匹配 `group` 与 `dataId`。
3. 配置编辑器支持常见配置语言的高亮、手动语言选择与按需语法校验。
4. 所有列表与搜索请求继续满足有界 IO，不读取配置正文，不为排序、填满页面或统计总数进行无界扫描。
5. 翻页、搜索和刷新不得静默丢弃未保存草稿。

## 非目标

- 不改变 etcd、ZooKeeper 的树形懒加载与现有搜索交互。
- 不搜索配置正文。
- 不为搜索结果计算准确总页数或提供任意页跳转。
- 不提供自动格式化、自动补全、代码折叠或 Minimap。
- 不把语法校验升级为 Rust 侧资源写入不变量；用户仍可明确强制保存或创建。
- 不修改 Nacos `contentType` 元数据。

## 一、Nacos 配置列表分页

### 基本交互

- 固定每页最多 50 条，不提供页大小切换器。
- 普通列表只显示当前页，提供“上一页”“下一页”和“第 X / Y 页”。
- Nacos 不再显示“筛选当前已加载资源”输入框。
- etcd、ZooKeeper 继续显示现有本地筛选与树形“加载更多”。
- 翻页时保留右侧已打开文档和未保存草稿；只有选择另一资源时才询问是否放弃修改。

### 刷新与远端变化

- 普通列表刷新当前页。
- 若当前页因远端删除而超过新的总页数，自动回退到最后一页，并提示列表已变化。
- 删除成功后重新加载当前普通列表页；在搜索视图中删除成功后，从搜索第 1 页重新执行查询。
- 新建成功后保留原列表页，右侧直接打开新配置；不假设或扫描新配置在列表中的页码。

### 搜索前后的位置

- 发起搜索时保存普通列表的页码、当前页结果与选中项。
- 退出搜索时恢复搜索前的页码与选中项，而不是回到第 1 页。
- 访问过的搜索页可在当前搜索会话中缓存，以支持“上一页”；刷新、修改关键词、退出搜索或切换连接时清空搜索页缓存。

## 二、Nacos 标识模糊搜索

### 查询语义

- 只在当前连接所选 namespace 内搜索。
- `group` 或 `dataId` 任一字段包含关键词即命中，两字段之间是 OR 关系。
- 关键词按普通文本处理，Atlas Registry 负责转换为 Nacos 模糊查询条件；用户不需要输入 `*`，输入中的通配符字符不获得额外语法含义。
- 匹配位置不限，例如 `trip` 可命中 `pre-robotaxi-trip` 与 `trip-service`。
- 大小写遵循 Nacos 服务端原生语义，客户端不承诺大小写不敏感。
- 保留现有 256 字节查询上限，空白查询不发起请求。
- 搜索只读取配置标识与必要列表元数据，不读取配置正文。

### 发起方式

- Nacos 只保留一个远端搜索输入框。
- 用户按 Enter 或点击“搜索”后才发起请求，不做输入即搜。
- 精确定位继续使用 `GROUP / dataId`，由独立的“定位”动作触发。

### 有界双路分页

- 后端分别执行 `dataId` 模糊查询与 `group` 模糊查询，并用复合游标维护两路进度。
- 单次用户翻页对每个字段至多读取一个上游页；单个 UI 搜索页最多返回 50 条。
- 两路结果合并后按完整 Nacos 配置标识去重。
- 当前组合页内先显示 `dataId` 命中，再显示仅 `group` 命中；各部分保留 Nacos 返回顺序，不承诺全局字典序。
- 合并与去重后允许出现不足 50 条的短页，不继续隐式扫描以填满页面。
- 搜索分页只提供“上一页”“下一页”和当前页码，不显示总页数，也不提供任意页跳转。
- 搜索结果高亮命中文字，并标识命中来源为 `dataId`、`group` 或两者。

### 搜索刷新

- 在搜索视图点击刷新时，保留关键词，清空复合游标、去重状态与已访问页，从第 1 页重新搜索。
- 搜索中的远端变化可能改变后续页组成；界面不承诺跨刷新保持结果位置。

## 三、可编辑语法高亮

### 编辑器底座

- 使用 CodeMirror 6 替换资源详情中的原生 `textarea`。
- 查看与编辑使用同一个可编辑视图，不提供预览/编辑切换。
- 首版启用行号、当前行高亮、括号匹配、`Cmd/Ctrl + F` 文内查找和 Tab 缩进。
- 不自动格式化，不自动修改换行符、缩进、注释或正文内容。
- 编辑器切换语言或重新渲染时必须保持草稿字节对应的字符串内容不变。

### 支持的语言

- JSON
- YAML / YML
- XML
- Java Properties / INI
- TOML
- Plain Text

### 自动识别

识别优先级如下：

1. 二进制/Base64 正文始终为 Plain Text，并禁用语法校验。
2. 使用可识别的 Nacos `contentType`。
3. 使用 `dataId`、etcd key 或 ZooKeeper 路径的文件扩展名。
4. 只对特征明确的内容自动识别 JSON 或 XML。
5. YAML、Properties/INI、TOML 没有类型或扩展名信号时回退为 Plain Text，避免把普通文本误判为结构化配置。

标题栏提供语言下拉框，用户可以覆盖自动识别结果。覆盖只影响当前文档的高亮和校验，不写回 Nacos `contentType`；手动选择 Plain Text 时跳过语法校验。

## 四、语法校验与保存门禁

### 校验范围

- JSON、YAML、XML、TOML：支持语法校验。
- Properties / INI：第一版只高亮；点击校验时明确提示当前语言仅支持高亮。
- Plain Text 与 Base64：不执行语法校验。
- 不做输入即校验；编辑时只实时高亮。

### 显式校验

- 编辑器标题栏提供“校验语法”按钮。
- 校验成功时给出非阻塞成功提示。
- 校验失败时显示首个错误的行号、列号和原因，并把编辑器定位到对应位置。
- 草稿再次修改后，旧校验结果立即失效。

### 保存与新建

- 点击“保存变更”或提交“新建资源”时，对当前识别/手动选择的可校验语言主动执行同一套校验。
- 校验失败时阻止本次提交，显示并定位首个错误。
- 用户可通过明确的“仍然保存”或“仍然创建”二次操作继续；随后仍进入现有变更确认、条件版本与脱敏审计流程。
- 强制提交只绕过前端语法校验，不绕过版本检查、生产确认、审计或远端结果不确定处理。

## 五、状态与接口设计

### Rust / IPC

- 扩展 Nacos 普通列表响应，提供当前页、总页数和是否存在前后页；不要把页码语义强加给 etcd/ZooKeeper 的游标树。
- 为 Nacos 双路搜索定义不透明复合游标，WebView 不解析服务端分页细节。
- 搜索项携带命中来源，供前端高亮和标签展示。
- 所有新增或修改 DTO 继续由 Rust 作为唯一事实源，并重新生成 `src/generated/*.ts`。
- 搜索游标必须校验版本、查询范围与页进度；错误游标返回结构化 validation 错误。

### 前端纯状态模块

- 将 Nacos 页式导航、搜索前页面快照、已访问搜索页与刷新/退出转换放入纯函数状态模块。
- 将语言识别、手动覆盖、校验能力判断和校验结果失效放入独立纯函数模块。
- React 组件只负责渲染、事件接线、调用 `src/registry.ts` 与 CodeMirror 生命周期。
- 选择另一资源前统一检查未保存草稿；翻页、搜索和刷新不得触发该放弃流程。

## 六、失败与边界场景

- 某一路搜索失败时整页失败，不以另一半结果伪装成功；错误保持可重试。
- 取消搜索时不提交部分页，也不覆盖当前已显示结果。
- 旧请求晚于新请求返回时不得覆盖新关键词、新连接或新页状态。
- 合并页可以为空但仍有下一页；此时显示“本页结果去重后为空，可继续下一页”，而不是“无匹配结果”。
- 只有两路游标都耗尽且当前结果为空时才显示“没有匹配的资源”。
- 配置在翻页期间被远端新增、删除或改名时，允许 Nacos 页码产生自然漂移；刷新是重建一致视图的显式入口。
- 语法解析器异常不得泄露正文到 Toast、日志、诊断包或审计；错误只包含语言、位置和脱敏原因。
- CodeMirror 对接不得绕过现有 1 MiB 内联 value 上限；超过上限仍走既有错误路径。

## 七、验收场景

### Nacos 列表与搜索

1. namespace 中存在超过 50 条配置时，普通列表显示第 1 页和准确总页数，下一页能看到第 51 条之后的数据。
2. 在第 N 页搜索后退出，恢复第 N 页、原选中资源和未保存草稿。
3. 关键词只命中后续普通列表页的 `dataId` 时，搜索第 1 次请求即可从全量服务端范围取得结果，而不是依赖已加载行。
4. 关键词只命中 `group` 时也能取得结果。
5. 同一配置的 `group` 与 `dataId` 都命中时只显示一次，并标记两个命中来源。
6. 双路合并形成短页时不额外扫描，下一页仍可继续。
7. 搜索结果不展示总页数；普通列表展示准确的当前页和总页数。
8. 搜索结果刷新后从第 1 页重建；普通列表刷新保持当前有效页。
9. 删除导致当前页越界时回退到最后一页；新建后保持原列表页并打开新配置。
10. Nacos 2.x 与 3.x 都覆盖上述普通分页、`dataId` 搜索、`group` 搜索与游标续页契约。

### 编辑器与校验

1. 明确 `contentType`、文件扩展名和保守内容识别分别选择正确语言。
2. 二进制/Base64 即使地址以 `.json` 结尾也保持 Plain Text 且不可校验。
3. JSON、YAML、XML、TOML 合法正文校验成功；非法正文返回可定位的首个错误。
4. Properties/INI 只高亮，并提示不支持严格校验。
5. 手动选择语言只影响当前编辑器，不改变 Nacos `contentType`。
6. 校验失败默认阻止保存与新建；明确强制操作后仍完整经过确认、条件变更和审计。
7. 编辑后旧校验结果失效；切换语言后按新语言重新校验。
8. CodeMirror 编辑、语言切换、校验与保存不会静默改变正文、换行符或注释。
9. 1 MiB 边界内的正文可编辑；超过边界仍由现有大值保护拒绝内联读取。

## 九、完成门禁

除针对本方案新增的测试外，完整通过项目既有本地门禁：

```bash
npm run format:check
npm run lint
npm run test:ui
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml
```

修改 IPC DTO 后还必须运行 `npm run generate:contracts` 并提交生成物。真实 Nacos 证据需要分别覆盖项目声明支持的 2.x 与 3.x 版本；在真实验证完成前，不更新 `docs/VERIFICATION.md` 声称能力已验证。
